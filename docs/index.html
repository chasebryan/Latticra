Latticra

Documentation entry point for contract-first systems architecture.

Overview Architecture Evidence Resources Repository

Project status: early-stage, evidence-bound systems architecture repository.

Latticra is a contract-first architecture for making system boundaries explicit before authority is granted.

Latticra is research and foundational engineering work for high-assurance infrastructure, Linux/Fedora integration, Lat language development, bounded intermediate representation work, runtime-boundary modeling, and AI-era tool-boundary planning.

The project should be read as an engineering record: contracts, boundaries, evidence, reports, and carefully limited claims. It is not presented as a deployed platform, certified product, production runtime, security product, or operating-system replacement.

No contract without identity. No authority without capability. No effect without a boundary. No promotion without evidence.

Architecture map

Latticra is organized as a small set of named layers. The current implementation posture is deliberately conservative: declaration, metadata, classification, and reports come before runtime effects.

Layer Role Current posture
Lat Contract and declaration language direction. Parsing, validation, diagnostics, and metadata lowering.
LIR Bounded intermediate representation and graph-shape metadata. Metadata reporting, not execution.
L-UI Operator-visible declaration and reporting surface. Report direction and validation records.
Nucleus Coordination, classification, task records, and task-boundary reports. Report-only task boundary modeling.
Runtime Boundary Classification line before operational behavior. Disabled-by-default boundary classification.
Latticra Seal Trust-boundary, request-boundary, policy-boundary, and tool-boundary planning. Report-only AI/tool boundary records.
Fedora/Linux Current host-facing validation lane and integration target. Narrow validation evidence, not distribution readiness.

Evidence posture

The repository distinguishes between what exists, what is being planned, and what is explicitly not claimed. This distinction is central to the project’s credibility.

present Foundation documents and public identity

Status records, strategy records, security policy, and documentation entry points exist in the repository.

present Deterministic validation and report surfaces

Current work emphasizes shell guards, C invariant tests, metadata records, and operator-visible reports.

guarded Fedora/Linux integration

The supported statement is narrow: disposable Fedora VM local RPM validation for a documentation-only local RPM.

not claimed Production runtime or OS replacement

Latticra does not currently claim active runtime enforcement, Fedora distribution readiness, certification, or operating-system replacement.

Latticra Seal

Latticra Seal is the project’s tool-boundary planning structure for AI-era automation and MCP-style tool invocation analysis. Its present value is clarity: it records what would be denied, why it would be denied, and what evidence supports that boundary decision.

  • Unknown tool, unsigned request, stale request, and replayed request cases are treated as blocked cases.
  • The runtime dry-run lane remains report-only and no-effect.
  • Guarded allowlist records improve classification, but do not grant authority or execute tools.
