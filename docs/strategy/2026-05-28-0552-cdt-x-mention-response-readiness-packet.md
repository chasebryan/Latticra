## Purpose

This packet prepares @Latticra to respond quickly and professionally when people comment on posts or mention the account.

The goal is not to win arguments. The goal is to be useful, calm, precise, and beautiful in public.

## Public Action Boundary

Replies, quote posts, reposts, likes, and follows are public actions.

Before taking any response action:

```text
inspect the exact mention or comment
classify the response type
draft the exact reply
confirm the reply does not overclaim
confirm cadence impact
get exact action-time approval before posting unless the owner has approved that exact reply path
log meaningful replies in the performance ledger
```

## Cadence Rule

Default:

```text
do not create bursts of public replies
preserve about 5 hours between outbound public actions when possible
prioritize direct technical questions over low-signal reactions
if multiple good comments arrive, batch them for review instead of replying to all immediately
```

Exception:

```text
urgent correction of a materially misleading claim about Latticra may be drafted immediately
public correction still needs exact action-time approval before posting
```

## Response Triage

### Reply

Reply when:

```text
someone asks a sincere technical question
someone asks what Latticra means or does
someone asks about evidence, limits, or status
someone makes a good-faith critique
someone adds a directly relevant insight
```

### Like Only

Consider a like only when:

```text
the comment is supportive but does not need a public answer
the commenter said something useful and the account has already replied recently
the comment is clear but low-context
```

### Do Not Engage

Do not engage when:

```text
the mention is bait
the thread is mostly outrage
the question demands claims beyond current evidence
the comment is abusive
the reply would only perform agreement
the topic is unrelated to Latticra's evidence-bound work
```

### What Is Latticra?

Reply:

```text
Latticra is early research around secure computing substrates: boundaries, evidence, receipts, denials, and operator-visible system behavior. The public standard is simple: explain what exists, what is missing, and what is not claimed.
```

### Is It Available?

Reply:

```text
Not as a production-ready product yet. The current posture is evidence-bound research and evaluation work. Public language should grow only as contracts, tests, reports, and reviewable artifacts grow.
```

### What Does Boundary Mean?

Reply:

```text
By boundary, we mean the place where a request becomes authority or gets denied. Latticra's interest is making that transition easier to inspect, test, and explain.
```

### Why Denial Matters

Reply:

```text
A denied action should still teach the operator something useful: reason, status, boundary, and next safe step. Silent failure and unexplained refusal both make systems harder to trust.
```

### Evidence Request

Reply:

```text
Fair question. The right standard is evidence before claims: contracts, tests, reports, receipts, and reproducible paths first. Stronger public claims should wait until those artifacts support them.
```

### Post-Quantum Question

Reply:

```text
The careful answer: no certified quantum-resistance claim. The Q-Seal posture is about planning with inspectable components, tests, limits, and language that does not outrun what has been verified.
```

### AI-Agent Authority

Reply:

```text
AI tools make intent cheap, which makes authority boundaries more important. Latticra's angle is to make requests, policy decisions, evidence, and denials visible before effects are trusted.
```

### Linux Or Open Source

Linux-native work matters because technical evaluators can inspect, run, challenge, and reproduce local paths. That fits the evidence-first posture better than asking for trust upfront.
