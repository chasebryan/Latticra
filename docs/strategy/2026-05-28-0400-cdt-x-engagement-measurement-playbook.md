## Purpose

This playbook keeps @Latticra's growth work professional and evidence-bound.

The account should grow by being useful: clear educational posts, thoughtful replies, sparse high-signal curation, and measured learning from what resonates.

## Growth Principles

```text
clarity over volume
trust over reach
education over promotion
evidence over claim
relevance over trend chasing
one public action about every 5 hours
```

## Audience Segments

Primary audience:

```text
systems engineers
Linux and open-source maintainers
security researchers
cryptography practitioners
technical evaluators
AI tooling builders
infrastructure operators
```

Secondary audience:

```text
curious technical learners
founders working near secure infrastructure
policy and research readers who value precise public claims
```

## Reply Criteria

Reply only when at least one is true:

```text
the reply teaches a useful boundary concept
the reply clarifies a limitation
the reply points to evidence or a public artifact
the reply asks a precise technical question
the reply thanks someone for a directly relevant insight
```

Prepare every reply through the mention response packet before posting.

Do not reply when:

```text
the account would only be agreeing vaguely
the thread is mainly outrage or status performance
the topic would pressure Latticra into claims beyond evidence
the reply would be better as a draft post later
```

## Mention Readiness

When @Latticra is mentioned:

```text
capture the mention URL
classify the comment
draft a short evidence-bound response
check the Non-Claim Guard
check the cadence impact
ask for exact action-time approval before posting
log meaningful replies after publication
```

Priority order:

```text
direct technical questions
good-faith critique
requests for current status or evidence
misstatements that need careful correction
supportive comments that merit a brief thank-you
```

## Curated Repost Criteria

Curate sparingly.

Allowed signals:

```text
Linux-native systems work
secure software supply chain
capability boundaries
cryptographic engineering
operator-visible evidence
AI tool authority and safety boundaries
formal methods or verification
open-source maintainer practice
```

Add commentary only when it teaches a Latticra-relevant concept.

## Daily Operating Rhythm

If posting:

```text
pick one approved queue item
confirm no public action happened within about 5 hours
post only exact approved text
log the post URL and timestamp
review after 24 hours
```

If not posting:

```text
review one draft for clarity
look for one relevant conversation
save one possible curation target
do not force engagement
```

## Weekly Review

Review:

```text
which posts earned follows
which topics earned useful replies
which wording caused confusion
which claims need tightening
whether visuals are still below the publication bar
whether the next week should be text-only again
```

## Performance Interpretation

Early account metrics are noisy.

Treat these as stronger signals:

```text
technical replies from relevant people
profile visits after educational posts
follows from systems/security/open-source readers
bookmarks on explanatory posts
quote posts that summarize the idea accurately
```

Treat these as weak signals:

```text
views without profile visits
generic likes
argumentative replies
low-context reposts
vanity impressions from broad hashtags
```

## Hashtag Rule

Default:

```text
no hashtags
```

Use a hashtag only if it is natural, specific, and not noisy. Never use broad engagement tags.

## Follower Growth Review Gate

After the first 10 approved posts:

```text
compare follower count against baseline
identify top 3 topics by useful engagement
remove weak draft patterns from the bank
prepare the next 20 drafts from what worked
decide whether visuals are ready to re-enter the queue
```

## Non-Claim Guard

Never let engagement pressure the account into claiming:

```text
production readiness
host protection
runtime enforcement
malware or ransomware prevention
certified quantum resistance
enterprise readiness
```

If asked directly, answer with current posture:

```text
early research
evidence-bound
no-effect evaluation where applicable
operator-visible reports and receipts
no stronger claim until implementation and tests support it
```
